# Typora 显示对比与修复记录

日期：2026-10-03 · 平台：Windows x64 · 参考：Typora 1.12.4 · 状态：本轮桌面对比已完成；完整 172 条验收仍未宣称通过。

本轮在 Typora 与 OpenTypora 实际窗口中打开同一份 [扩展功能样例](fixtures/advanced-feature-sample.md)，两者缩放均为 100%。比较覆盖 YAML、标题、目录、行内引用与脚注、五类警告框、图片、表格及公式。样例与配套图片是独立测试素材，不使用用户原有文档。

本记录补充 [功能观察记录](Typora-功能观察记录.md) 的证据：此前未确认独立样例打开成功，本轮已经完成同样例显示观察。此前的未验证记录仍保留其当时的证据边界。本机显示结果不等于 Typora 官方规格，也不证明其他主题、缩放、窗口尺寸或全部语法已经完成验收。

## 1. 状态口径

- **已观察**：本轮在两款应用的实际窗口中确认了修复前的显示差异。

- **复核通过**：必须记录复核构建、样例、设置与实际结果，不能由代码阅读、单元测试或构建成功代替。

本轮显示比较使用 Github 类排版。最终复核条件：Windows x64、Node.js 24.18.0、npm 11.7.0、Electron 44.5.1，最新本地构建，100% 缩放，同一样例文档，隔离用户数据目录。修复后的状态按实际窗口证据记为“复核通过”；这不替代完整 172 条验收。

| VIS-02 | 一级、二级标题字号与参考排版不同，活动标题与预览标题的样式也需要一致。 | Github 类排版统一活动/预览标题的字号、字重、行高与下边框；当前实现的 h1/h2 分别为 `2.25em`、`1.75em`。这些是实现值，不能冒充参考软件的通用规格。 | 复核通过 |
| VIS-03 | 预览继承 CodeMirror 的 `pre-wrap`，生成 HTML 的结构换行被显示成额外空行，段落与复杂块的垂直间距扩大。 | 阅读预览使用正常空白折叠；代码、YAML 与需要保留空格的内容单独保留相应规则。生成 HTML 的格式化换行不再作为正文空行。 | 复核通过 |

| VIS-05 | 正文目录的边框、颜色和层级缩进与参考不同，呈现为带框面板。 | 调整目录外框、链接颜色、字号、层级缩进与段距；目录继续由文档标题生成，区别于侧边栏大纲。 | 复核通过 |
| VIS-06 | 为解析引用而向每个预览块附加脚注定义，使多个块重复生成尾注区域。 | 阅读块利用定义解析引用后移除重复生成的尾注区域；定义在原文位置呈现，引用与返回链接定位到原文范围。 | 复核通过 |

| VIS-08 | 单独成段的图片与参考的居中显示不同。 | 对独立 Markdown 图片及独立 HTML 图片应用居中规则，保持尺寸限制与原始资源引用。 | 复核通过 |
| VIS-09 | 表格未占满正文阅读宽度，各列宽度与参考的等列布局不同。 | 表格使用正文范围内的全宽与固定列布局；保留各单元格的左、中、右对齐和内容。 | 复核通过 |

| VIS-11 | 数学公式刷新后编号继续累加，重复渲染同一文档得到不同编号。 | 公式编号由当前文档中的顺序确定；渲染器状态重置，并使用明确的公式索引，刷新后编号稳定。 | 复核通过 |

## 4. 本轮补充集成

Editor、Services 与 Workspace 模块的独立 worktree 成果已经合并到 root。root 本轮继续补齐应用装配、共享样式与渲染、命令与设置的实际消费者、桌面服务以及跨模块行为。此处的“已经合并”描述代码状态，不表示完整产品验收已经通过。

严格模式与大纲的同步也已补齐：严格模式保留标准标题规则；宽松模式允许顶层 `###Header`。大纲与 Worker 请求使用同一严格模式设置，结果缓存区分该设置，并排除旧设置下的迟到结果。标题位置从原文 UTF-16 范围取得，不从兼容性投影后的字符串取偏移；代码、YAML、公式和字面 HTML 受到保护。CRLF 下的空标题及普通 HTML 块空行结束边界已有专项回归。
