## 2. 产品定位与核心判断

OpenTypora 是以本地 Markdown 文件为中心的桌面查看与编辑器。用户直接在排版后的正文中写作，必要时切换到 Markdown 源码；大纲、文件导航、搜索和导出围绕同一份文档工作。

复刻重点应放在“编辑时仍然像在阅读文档”的连续体验。只有 Markdown 渲染页面和文本输入框，不能满足这一目标。决定体验的关键是光标、选区、输入法、块结构转换、撤销，以及源码和渲染内容之间的一致性。

平台基线是此次实际调查的 Windows 桌面版。目录名称中的 Python 不足以确定技术栈，本规格不绑定实现语言。OpenTypora 使用自己的名称、图标和实现资源，复现参考产品的功能与交互。通过 agent 一次性完成全部能力是开发组织方式，不能据此省略保存恢复、源码一致性、输入法或格式转换的验收。

### 2.1 目标用户与任务

| 用户 | 主要任务 | 成功标准 |
| --- | --- | --- |
| 日常写作者、学生 | 笔记、读书记录、长文 | 连续输入不被标记和工具面板打断 |
| 开发者、技术作者 | README、代码说明、技术文档 | Markdown 可移植，代码与结构正确 |
| 产品与项目人员 | PRD、会议纪要、任务清单 | 表格、任务、标题导航和导出顺畅 |
| Markdown 阅读者 | 打开第三方文档、检索内容 | 本地打开快，链接与图片正确，可保护原文 |

### 2.2 完整交付目标

1. 在一个正文区域完成查看、输入、选区和格式编辑。
2. 保持可读、可移植的 Markdown 文件，不依赖专有数据库才能读取正文。
3. 保护未保存内容，失败时保留恢复路径。
4. 让常用动作通过键盘完成，也提供可发现的菜单入口。
5. 完整实现调查中发现的 Markdown 扩展、图片上传、多格式导入导出、主题定制、高级设置和 Windows 集成。
6. 每一个可执行菜单项、设置项和快捷键都有实际行为、上下文可用状态及验证记录。

### 2.3 完整范围与参考映射

文件生命周期、即时编辑和源码、全部已发现段落/格式命令、公式及三类图表、脚注/目录/YAML/警告框、文件导航与搜索、图片管理与上传、全部已发现导出类型及自定义转换、打印、五类内置主题体验与自定义主题、写作辅助、统计、七类设置、帮助/更新/高级配置和 Windows 集成全部必须完成。外部转换器和上传工具允许作为显式依赖，依赖检测与配置属于交付内容。

调查没有发现云同步、多人协作、AI 写作、插件市场或移动端功能，本规格不凭空增加这些能力。只读保护、冲突比较和部分错误恢复规则是 OpenTypora 的明确产品决策（D），不能声称已在 Typora 实测。

许可证/购买、Typora 官方站点和国内服务器是参考厂商服务入口，也保留在观察清单中。OpenTypora 的映射见第 12.3 节：关于、更新、帮助、反馈和发行信息必须有对应能力；不连接 Typora 激活服务或冒用其序列号。OpenTypora 的发行授权采用自有规则，这属于服务归属调整，不用于缩减编辑器功能范围。

### 3.2 导航模式

2026-10-03 用户调整：左侧标签从左到右为“文件、大纲”，新窗口默认显示文件栏。文件栏顶部提供文件名过滤，按文件名做不区分大小写的字面匹配，清空后恢复原文件树或摘要列表。子目录匹配可通过完整路径区分；无匹配时明确提示。跨文件内容搜索合并到文件栏，通过搜索按钮或 `Ctrl+Shift+F` 进入，保留匹配选项与结果定位；文件名过滤同时限制内容搜索结果显示，不再设置独立“搜索”标签。

- **大纲**：按标题级别缩进展示结构，当前章节高亮，点击滚动到对应标题。允许折叠是参考设置中可见能力。
- **文件树**：展示当前根目录和子目录，按需展开，标记当前文件。
- **文档列表**：展示文件名、所在目录、时间及正文摘要；时间口径应明确为修改时间。
- **跨文件搜索**：在根目录内返回按文件分组的匹配。此次只确认界面，结果分组及索引策略是 D。
- **快速打开**：按文件名检索，结果同时展示路径以区分同名文件。

文件树、大纲和目录正文 `[TOC]` 是三种不同功能：文件树组织磁盘文件，大纲是界面导航，目录是文档内容。

## 5. 文档与文件生命周期

### 5.1 DOC-01：新建与打开

**参考**：文件菜单提供新建、新窗口、打开文件、打开文件夹、最近文件和快速打开（B）。打开对话框可见多种 Markdown/文本后缀。此次未确认新窗口或样例文档成功打开（C）。

**需求**：

1. 新文档有独立标识、内存正文、选区、撤销历史和恢复草稿；首次保存前不伪装为已写入磁盘。
2. 打开文件后保留路径、编码和换行风格，并将该窗口的文件导航根目录自动关联到文件所在目录，直接显示同目录下其他 Markdown 文件。再次打开其他目录的文件时更新关联，各窗口独立；打开失败或取消不改变现有关联。目录变化刷新文件列表，切换目录清除旧文件名过滤。默认写出 UTF-8。无法识别编码时提供选择，不静默产生乱码。
3. 已打开路径再次打开时定位到已有文档；多窗口共享同一路径时应有明确冲突策略。
4. 打开文件夹更新导航根目录，不自动修改任何文件。根目录不限制正常打开外部 Markdown。
5. 目录为空、路径不存在、无读取权限、文件被删除时给出具体状态，不用空白正文替代错误。
6. 拖入文件夹、Markdown、图片、可导入文件分开处理；插入图片与打开文档不能混淆。

### 5.2 DOC-02：保存与外部变更

文档状态至少包括：未命名空白、未命名已修改、已保存、已修改、保存中、保存失败、外部冲突、只读。

| 场景 | 目标行为 |
| --- | --- |
| 未命名文档保存 | 选择路径；成功后绑定路径并清除未保存标记 |
| 已命名文档保存 | 完整写入成功后清除标记；保存中继续输入不能漏掉新内容 |
| 另存为 | 新路径生效前保留原路径；说明图片相对路径的处理 |
| 关闭/切换已修改文档 | 提供保存、放弃、取消；取消保留当前文档 |
| 自动保存关闭 | 不因查找、滚动或模式切换而自动写盘 |
| 写盘失败 | 保留正文、撤销历史及草稿；显示原因和重试动作 |
| 外部更新且本地未修改 | 可重载并保留合理的阅读位置，告知更新 |
| 外部更新且本地已修改 | 显示冲突；提供比较、保留本地/另存副本或重载选择 |
| 文件外部删除 | 保留内存正文；提供重新保存路径 |
| 只读文件 | 仍可阅读、查找、导出；编辑保护清楚可见 |

保存采用防止半写入的实现策略；具体文件系统实现由技术设计确定。文件正文和依赖图片资源的成功状态要分别检查，不能只验证 `.md` 存在。

### 5.3 DOC-03：自动保存与恢复

**参考**：自动保存、切换文件保存上一文件、恢复未保存草稿入口可见（B），未验证恢复结果。

**需求**：默认启用本地恢复草稿；自动覆盖原文件默认关闭。二者分别设置和说明。建议草稿在内容变更后的 2 秒空闲期落盘，并有最长 10 秒的持续输入保存间隔，属于 D。

异常退出后列出恢复候选及时间，先恢复为可检查的内容，不静默覆盖已有磁盘文件。恢复草稿有来源路径和版本标识；成功保存后可清理对应草稿。清理策略不能提前移除尚未成功保存的内容。

### 5.4 DOC-04：文件管理与系统定位

“移动到”在新路径写入成功后更新会话路径、导航选中项、历史及相对资源引用；目标冲突必须可取消。“保存所有打开的文件”按文档记录独立结果，未命名文件逐个处理，单个失败不能被总成功提示掩盖。多窗口关闭需处理每个窗口的未保存会话。

文件属性展示路径、文件大小、编码、换行、磁盘修改时间和文档状态；未保存文件明确显示暂无磁盘属性。打开文件位置调用资源管理器定位，侧边栏定位展开祖先目录并选中文件。删除使用可恢复的系统机制并明确告知，失败不移除会话。最近文件/文件夹支持记录开关、缺失项提示和清除历史；清除历史不删除磁盘文件。

## 6. EDIT：编辑体验与源码一致性

### 6.1 EDIT-01：即时渲染

正文默认显示排版后的 Markdown。光标进入某块时，必须能直接编辑该块；离开时形成对应排版。不要要求用户不断手动切换整页预览。

1. 光标进入标题、引用、列表、表格、代码时仍可连续键盘导航。
2. 未闭合标记保留为可编辑文本，不能丢失输入、消失光标或改变前后文。
3. 对当前块显示源码的偏好可配置。是否显示标记要有一致的边界，点击标记也能编辑。
4. 鼠标选区可跨多个块；跨块删除或格式操作不得破坏未选中块。
5. 中文输入法组合阶段不触发结构转换、智能标点重写和格式自动闭合；组合提交后再解析。
6. 粘贴大量文字、插入图片与图表渲染不得阻塞输入；离屏内容可延迟布局。
7. 输入导致重排时保持光标可见，避免正文大幅跳动。

### 6.2 EDIT-02：源码模式

**参考 A**：`Ctrl+/` 可切换源码模式，显示 Markdown 标记、语法颜色、行号及当前行背景；此次源码视图隐藏了左侧大纲，底部有退出入口。切换回来仍显示原文。精确选区与滚动位置往返未完整验证。

**需求**：

- 两种模式共用同一文档内容和修改状态，禁止维护两份独立可编辑正文。
- 无编辑的模式切换不能改写 Markdown、自动格式化表格、重编号列表或触发保存。
- 切换时按文本位置/块定位映射光标与选区；无法精确映射时定位到同一块并保留选区信息。
- 源码模式显示行号、当前行、语法高亮；支持换行、缩进与搜索。
- 在源码模式输入合法或不完整语法，切回后都不丢字；未知语法原样保留。
- 两种模式间共享可理解的撤销链；模式切换自身不占据正文撤销步骤。

### 6.3 EDIT-03：撤销、选区和剪贴板

**参考 B**：撤销重做、复制 Markdown/纯文本/HTML、简化格式复制、纯文本粘贴、整行移动和删除范围都有菜单入口。

**需求**：连续文字输入按自然输入分组；加粗、任务勾选、表格行列操作、图片插入、一次替换分别作为可撤销动作。跨模式撤销不能只恢复视觉而不恢复源码。

剪贴板需明确处理 Markdown 文本、普通文本、富文本 HTML、图片和文件路径。默认保留 Markdown 内容；纯文本粘贴移除富文本包装。复制为 HTML 需提供可用的渲染结构；复制 Markdown 则提供源码。重复执行复制粘贴不产生无意义的嵌套样式。

空选区时的整行复制/剪切作为可配置行为，不默认让用户误剪整行。剪贴板不可用时显示失败，不清空现有选区或正文。

### 6.4 EDIT-04：语义选区与范围操作

实现全选、选择段落/块、当前行/句、当前格式文本、当前词；文首/文末、行首/行尾、所选内容跳转；整行上移/下移；删除块、当前行/句、格式文本、词。按词处理中文和英文时在帮助中说明分词口径。当前格式范围由语法节点确定，不能以最近的星号粗略截断嵌套格式。删除或移动都进入同一撤销事务；没有适用上下文时禁用。单行、文首、文末、空块和跨块选择必须有确定结果。

### 6.5 EDIT-05：输入辅助与文本规范

配对括号/引号与配对 Markdown 标记分别配置；连续输入、转义字符、选区包裹和退格成对删除都有规则。Emoji `:名称:` 补全可键盘选择/取消，不把代码块和普通冒号错误转换。

智能标点支持输入时转换和渲染时转换两种模式，包含智能引号、破折号及 Unicode 标点解析；渲染时转换不能污染源码。拼写检查支持语言选择/自动检测、错误标记和建议替换；字典不就绪时给出状态而不中断写作。系统表情与符号入口使用 Windows 提供的能力。

当前文档 LF/CRLF 与新文件默认换行分别设置。转换换行可以撤销；“保存时文末添加空行”按明确策略落盘。首行缩进、显示 `<br/>`、保留单换行符及连续空格在编辑和导出中分别生效；不能在仅浏览时擅自删除空白。

## 8. NAV 与 SEARCH：导航和检索

### 8.1 大纲

大纲由文档结构生成，标题变化后更新，忽略代码块内的 `#`。支持空标题、同名标题、标题级别跳跃及多语言标题。点击标题只改变定位，不修改文档。目录折叠状态按文档或会话记忆，不写入正文。

### 8.2 文件树与摘要列表

参考 A：两种视图可通过 `Ctrl+Shift+3/2` 切换。摘要列表显示名称、路径、时间和内容摘要。

根目录展开采用懒加载；大目录不一次扫描所有正文。隐藏文件、支持后缀、排序规则配置清楚。外部新建/删除/改名后刷新导航；同名文件显示路径。文件改名、移动、删除属于显式操作，失败保留原状；删除优先进入系统回收站。

### 8.3 文内查找与替换

参考 A：顶部查找输入框，匹配高亮，当前/总匹配计数，上下命中按钮；可见大小写、全词及正则选项。输入实测出现 `1/4`。替换入口 B，替换执行 C。

1. `Ctrl+F` 打开查找并聚焦；有选区时可预填选区文本。
2. 回车/Shift+回车定位下一个/上一个命中；循环查找时说明状态。
3. 0 个命中、空关键词、无效正则均有清楚反馈；无效正则不触发替换。
4. 用同一文本位置体系处理源码和即时模式；需明确搜索是否覆盖标记、代码、隐藏脚注与链接地址。
5. 单次替换和全部替换可撤销；全部替换前展示数量；只读文档禁止替换。
6. 关闭查找后恢复编辑光标；搜索文本不得被误输入正文。

### 8.4 快速打开与跨文件搜索

参考 A：`Ctrl+P` 弹出文件名检索面板，结果含目录；`Ctrl+Shift+F` 打开侧边栏搜索。实际筛选、结果跳转和跨文件命中未验证。

快速打开使用上下键选择、Enter 打开、Esc 取消，同名文件展示完整或相对路径。跨文件搜索按文件分组并展示上下文，点击结果定位。扫描异步进行，可取消；旧查询结果不能覆盖新查询。读取范围是用户当前打开的根目录，避免无边界扫描磁盘。

## 9. ASSET：图片与附件

参考 B：插入图片策略、对本地/网络图片应用规则、相对路径、添加 `./`、自动转义 URL、上传服务与 YAML 上传设置。当前上传服务为“无”。没有执行图片复制或上传（C）。

- 路径含空格、中文、括号、`#`、Windows 分隔符时正确处理。

- 单张复制、重命名/移动、删除图片文件，与移除正文图片引用分别处理。删除文件前说明对其他引用的影响。
- 批量复制/移动/上传只处理本次快照中的图片集合，逐项报告结果，重复引用去重，部分失败保留可重试状态。
- 重新加载所有图片清理加载缓存并重试；图片根目录作为文档配置参与路径解析，优先级在帮助中说明。

### 9.2 上传适配

必须实现 PicGo-Core（命令行）、PicGo（应用）、PicList、自定义命令四类适配及“无”状态。为每种适配定义配置、依赖检测、测试上传、批量输入、返回地址解析、超时、取消和失败反馈。第三方工具承担的存储服务不需在编辑器里重复实现，但不能只显示工具名称而没有可用连接。

支持用户手动上传，以及用户启用的插入时自动上传/YAML 上传规则。只有在规则启用且用户执行相应插入或上传动作时调用配置服务；仅打开未知文档不触发上传。成功后以文档版本和图片标识检查原引用仍存在，再回写远程地址；失败保留本地地址。上传成功后用户撤销应恢复原引用；远端文件是否删除不能与正文撤销混淆。

## 10. VIEW 与 STAT：阅读和写作辅助

### 10.1 主题与缩放

参考 B：Github、Newsprint、Night、Pixyll、Whitey 五个主题；外观设置支持字体大小、缩放、深色独立主题、主题目录与获取主题。当前主题为 Github。

### 11.3 导出流程与失败处理

用户选择格式 → 检查依赖/资源 → 选择目标路径及参数 → 冻结本次导出内容版本 → 生成 → 显示成功或错误 → 可选打开结果。

导出未保存文档可以基于内存内容进行，不强迫覆盖原文件。期间继续编辑不污染本次导出快照。取消后不留下被误认成成功结果的半成品；输出目录无权限、转换器缺失、公式/图表失败、图片不可读分别报告。

YAML 覆盖导出设置、导出后打开文件/目录和自定义命令均必须实现，并由用户明确配置。文档元数据可以覆盖声明的排版字段，不能自行提升到任意执行命令。自定义命令使用用户配置的执行规则，正确处理带空格路径、参数、退出码、超时与日志。PDF 分页覆盖长表格、长代码、公式、中文字体、页首页尾与目录锚点，不能只检查文件是否创建。

### 11.4 导出配置管理

支持从模板添加配置、命名/编辑、删除、上下排序；改变顺序同步到导出菜单。通用项包括默认输出目录、Pandoc路径自动检测/指定和默认后置动作。每个配置有稳定ID，模板只是初始值，不覆盖用户修改。删除配置不删除已生成文件。恢复默认配置可预览变更，用户自定义配置有备份路径。

### 11.5 IMPORT-01：导入

参考 B：文件菜单有导入入口，文件设置规定可导入文件拖入后转换。具体输入格式和转换结果此次未完成验证（C），不能声称与导出格式完全对称。

OpenTypora 使用转换器的输入格式能力注册表，至少为 HTML、Word `.docx`、OpenOffice、RTF、Epub、LaTeX、MediaWiki、reStructuredText、Textile、OPML 及其他声明的 Markdown 方言提供导入路径（D）。导入对话框显示支持类型和依赖，用户选择输入后形成新的可编辑 Markdown 会话，原文件不改写。图片提取到明确的资源目录；表格、标题、列表、链接、公式映射到支持的语法。无法保真的结构生成诊断报告，不静默丢失。取消、文件损坏、依赖缺失、权限不足均保留原输入。PDF不因“能导出”而被自动声明为可语义导入。

### 14.2 可靠性与兼容

无操作打开、浏览、源码往返之后，文件字节保持一致。只修改局部内容时尽量保留未编辑区域的标记、换行及空白。未知语法不丢弃。保存失败、外部冲突和恢复失败均不能吞掉内存正文。

### 14.3 无障碍与文档内容处理

主要菜单、搜索、弹层和设置可用键盘及辅助技术操作，焦点位置可见；工具图标提供名称。颜色不是表示状态的唯一方式。Markdown 中的脚本和事件处理属性不得执行；未知链接协议、外部资源和命令需要独立处理策略。验收包含损坏文档、特殊协议和脚本输入。

4. 无正文丢失、静默覆盖、不能恢复或两种编辑模式内容分叉的缺陷。
5. 不交付空菜单、模拟成功、固定演示数据或只可渲染不可编辑的正文。
6. Windows安装包/可运行发行物、转换器/上传依赖说明、用户帮助、语法兼容矩阵、测试报告一并提供。

功能覆盖按“需求ID → 命令/设置键 → 实现位置 → 验收用例 → 结果”追踪。UI入口完成、服务实现完成、失败路径完成、集成验证完成分别记录，只有四者齐备才能标为完成。

## 17. 待确认与待补测

### 17.1 开发基线决策

| 项目 | 本规格采用的决策 | 补充说明 |
| --- | --- | --- |
| 平台 | Windows x64桌面完整功能 | 未调查macOS/Linux行为，不声称已对齐 |
| 多文档形态 | 每窗一个活动文档、多个窗口、文件导航与窗口切换 | 标签页不是此次观察要求 |
| Markdown兼容 | 本次全部已发现基础语法与扩展 | 建立逐项兼容矩阵，无延期项目 |
| 技术方案 | 实现团队选定，必须满足位置映射、IME、历史及渲染要求 | 目录名称不绑定Python |
| 自动保存 | 恢复草稿开启，覆盖原文件默认关闭 | 两种能力分别配置 |
| 图片策略 | 无特殊操作为初值；复制/移动/上传/路径策略全部可选 | 未保存文档有临时资源机制 |
| 公式与图表 | 全部实现，开关是用户偏好 | 关闭解析不代表未实现 |
| 自定义/外部命令 | 全部实现，由用户配置和明确启用 | 文档字段不能擅自指定可执行程序 |

### 17.2 参考产品补测

新建窗口/打开样例、实时键入转换、中文输入、格式包裹与取消、撤销重做、列表续项、任务勾选、表格增删移动、代码语言切换、公式与Mermaid渲染、脚注目录导航、图片迁移、自动保存恢复、替换、实际导出、外部冲突与只读行为。

这些项目仍有完整的 OpenTypora 需求及验收标准，待验证不等于缺少开发定义。后续发现 Typora 行为与本规格不同，应分别记录“参考观察更新”和“OpenTypora 产品决策”，不要自动改变已确定的目标。
